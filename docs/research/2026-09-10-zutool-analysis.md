# 競合分析: 頭痛ーる（ずつーる）

作成日: 2026-09-10。公開情報（公式サイト・プレスリリース・レビュー記事・ユーザー投稿）に基づく。
実機での操作確認は未実施 — 通知のリードタイムや画面遷移の細部は未確認（§7）。

## 1. 基本情報

| 項目 | 内容 |
|---|---|
| 運営 | 株式会社ベルシステム24（2013 年リリース、気象予報士が開発、医学監修あり） |
| 規模 | **累計 2,000 万 DL**（2024-12）、**月 120 万件**の体調記録を収集、月間アクティブ約 120 万人（公式サイト記載） |
| データ | 気圧予報は**気象庁**提供。ユーザー記録との組み合わせで「精度の高い気象病予報」を標榜 |
| 学術 | 記録データを用いた研究がアメリカ頭痛学会誌に掲載（Katsuki et al. 2023, Headache — 低気圧・気圧変化・高湿度・降雨が頭痛と関連） |
| 対応 | iOS / Android。日本国内（気象庁データ、無料は全国 11 地点、有料で都道府県別） |

## 3. 仕組みの読み

- 予報は**集団統計**。気象庁の気圧予報に、全ユーザーの記録から得た「この気圧変化でどれだけの人が不調を訴えたか」を重ねて注意・警戒を出す。
- **個人の記録は予報にフィードバックされない**（痛みノートは振り返り用）。「みんなの痛みナウ」も集団の現在値。
- アラートは「気圧が通常より大きく下がる時」がトリガー。上昇側・湿度・気温は予報の主軸ではない（グラフは気圧中心）。
- サーバー依存: 予報配信・記録同期・課金復元がすべてサーバー経由。値上げ理由も、後述のログイン障害もここに由来する。

## 4. ユーザーの不満（レビュー・投稿から）

- **広告**: 「広告が増え、開く際に待たされ、画面に常時表示される広告が邪魔」
- **課金誘導**: プレミアムへの切り替えを尋ねるウィンドウが繰り返し出る、不意打ちの CM 風ウィンドウ、画面のちらつき
- **レビュー催促**: 起動のたびにレビューを求める通知（Google Play コミュニティに相談が立つほど）
- **復元・サポート**: 機種変更後にログインできず「購入復元」が何度もエラー、問い合わせ 2 回に返信なし。年払い中のため課金だけ続く（[note の退会記](https://note.com/melodymika/n/n7d53b192098c)）
- **理解の壁**: 「気圧の変化がグラフで出ても、原因と結果の関係がすぐにわかるわけではない」
- 一方で「翌日までの気圧と天気が分かれば十分」「無料で満足」という声も多い。基本体験の評価は高い。

出典: [Good!Apps](https://good-apps.jp/media/app/30445)、[App Store レビュー](https://apps.apple.com/jp/app/id602991338?see-all=reviews&platform=iphone)、[APPLION](https://applion.jp/iphone/app/602991338/review/)

## 5. 強み

1. **認知と規模**: カテゴリの代名詞。12 年分・月 120 万件の記録は誰も持っていない
2. **信頼の記号**: 気象庁データ、気象予報士開発、医学監修、学会論文
3. **記録の幅**: 薬・生理・メモ・家族・ペットまで「体調の家計簿」として厚い
4. **ウィジェット**: 気圧をホーム画面で見られる。無料 1 時間 / 有料 24 時間という課金導線にもなっている
5. **10 日先予報**: 予定を立てる用途（旅行・イベント）に効く

## 6. 弱み・隙（zutsuu が刺せる場所）

| 隙 | 頭痛ーる | zutsuu の対応 |
|---|---|---|
| 個人化がない | 集団統計。記録は振り返り専用 | 記録 → 個人の閾値補正 → 通知が当たる（設計書 §6.2、PersonalRisk 実装済み） |
| 気圧偏重 | 予報は気圧中心 | 5 要因（気圧変化・絶対気圧・湿度・降水・気温変動）。Katsuki 2023 はこの構成を裏付ける |
| 日本限定 | 気象庁データ・固定閾値 | WeatherKit + 地点別パーセンタイル（§5.1）でグローバル |
| サーバー依存 | 値上げ・ログイン障害・復元エラー・サポート無応答 | 端末完結。ログインもサーバー費用も存在しない（§3） |
| 広告体験 | 常時表示・誘導ポップアップ・レビュー催促 | Tier 0（メイン画面・記録）は広告なしの聖域（§8） |
| 通知の設計 | 「下がる時」のアラート。事前の行動時間や就寝中の扱いは不明 | 90 分前の事前通知、静穏時間、起床時通知（riskengine-api §5） |
| 「関係が分からない」 | グラフを見ても因果が読めない | ホームの「いま・次の通知・要因 1 行」（設計原則 §1.3）、ログに天気の特徴を添える |

## 7. zutsuu が学ぶべき点・取り入れ検討

1. **ウィジェット**（v1.0 候補）: 頭痛ーるの主要導線。「次の通知」と「いまのレベル」を出す小ウィジェットは Tier 0 の延長として自然。
2. **服薬の 1 タップ**: うちの通知の目的は「薬を飲む時刻を知らせる」（設計書 §4）。記録に「薬を飲んだ」を足せば、通知 → 行動 → 効果の輪が閉じる。頭痛ーるの薬記録は種類まで持つが、うちは 1 タップの規律（§6.1）を守って「飲んだ／飲んでない」だけにする案。
3. **月別レポート**: v1.1 の相関レポート（§6.3 記述主義）と統合できる。
4. **10 日先**: WeatherKit の hourly は 10 日先まで取れるが、気圧の精度は 3 日を超えると落ちる。72 時間の判断は据え置き、表示だけ延ばすかは要検討。
5. **やらないこと**: 常時広告・課金ポップアップ・レビュー催促・ログイン必須。頭痛ーるの不満はほぼ全部ここに集中しており、設計書 §1 が想定した「広告で低評価」の具体像でもある。

## 8. 他の競合（簡易）

- **ウェザーニュース「天気痛予報®」**: 9 地方の地域別、気圧・気温から頭痛・関節痛が出やすいタイミングを予報。天気アプリの一機能で記録・個人化はない。
- **ミグル**: 記録特化のシンプル頭痛日誌。予報なし。
