## 決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| ホームの above the fold | 上から **今のリスク → 次の通知 → 1 タップ記録** の 3 要素 | 設計原則 §1.3。再訪の最初の問いに即答し、記録の入口を最短に |
| 「次の通知」の中身 | **通知と同じ文面**（`AlertNotifications.content` の title）と発火時刻 | 通知が来なくても画面で同じことが分かる。通知は個人化済みなので「次の通知」と明示してレベル表示の汎用性と区別する（`appcore-api.md` §3） |
| 記録タブ | **残す**（きあぼうと休む・見え方の設定はそちら）。ホームには短い版 `KiabouQuickCheckIn` | タブ 3 つは上限内。ホームの記録は 2 秒動線、タブは滞在の場 |
| 記録の見返り | 記録直後に**累計の記録日数**を出す。「あと N 日で〜が選べます」は着せ替えの実装（Task 5）と同時 | 選べないものを「選べます」と言わない |
| 忘れた翌日 | 「昨日の記録がありません」の類は出さない | 設計原則 §1.2（罰しない）、設計書 §6.7 |
| オンボーディング | 4 画面固定: 何のアプリか → 位置情報 → 通知 → 体質申告（任意）。スキップ常時表示、ドット常時表示 | 設計原則 §2。権限は理由と一緒に求める |
| 配色 | `KiabouPalette` を public にしてアプリ全体で使う。3 色 + 紙白 | 設計原則 §2 レイアウト。きあぼうの世界に揃える |
| 数値 | monospaced digit、大きく | 気圧・pt は計測値。読み間違いを減らす |

## タスク

### Task 1: KiabouUI の共有部品
`KiabouPalette` を public 化。記録ボタンを `RecordButton` に切り出し、`KiabouCheckInView` と新設の `KiabouQuickCheckIn`（ステージ + 2 ボタン + 状態 + 累計日数）で共用。

### Task 2: パイプラインの表示用状態
`ForecastPipeline` に `nextAlert`（予約した通知のうち発火が最も早いもの）と `recordedDays`（`CheckInStore.recordedDayCount`）を追加。

### Task 3: ホーム
`TodayView` を ScrollView + カードに組み替え。ヒーロー（レベル・pt・要因）→ 次の通知 → 記録 → 時間別 → 寒暖差 → 帰属。

### Task 4: オンボーディング
`OnboardingView`（`TabView(.page)`）。完了フラグは `AppStorage("onboarding.completed")`。`RootView` で出し分け。体質申告のトグルは `SensitivityToggles` として設定画面と共用。

### Task 6: 背面遊泳モード（2026-09-10 追加、ユーザー提案）
きあぼうを画面固定ではなく UI の後ろで泳がせるモード。仕様は `kiabou-integration.md` §3.1。

### Task 5（未着手）: 着せ替え
`assets/kiabou/variations` の素材を Resources に取り込み、累計日数で解放、選択を保存、`KiabouScene` で差し替え。
